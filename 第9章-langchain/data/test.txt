# D9 语音交互与任务编排需求分析 v0

- **Skill 版本**：requirement-to-design v1.6.0
- **需求来源**：产品截图（2026-09-15）
- **状态**：v0，待产品/算法/嵌入式确认

## 1. 需求理解与范围

### 1.1 目标

机器人空闲时常驻等待唤醒。机体麦阵沿用系统 Speech SDK 录音；外接 USB/无线麦需要应用提供 PCM。唤醒词“嗨，PUDU”命中后进入语音交互、播放“我在”、灯效从待机切换到交互灯。非指令语音仅回答；指令语音创建并执行导航、播放、动作或组合任务。

每次唤醒后开启一段最长 15 秒的完整语音会话。每轮 TTS 完成后持续监听最多 5 秒；ASR 失败累计至第 3 次时退出会话。非失败的问答不消耗失败次数。任一限制先达到即自动退出，继续交互必须再次唤醒。任务完成、失败或暂停后复位；若有被中断任务，机器人仅通过语音询问是否恢复，确认后恢复，否则清除。任务队列按顺序调度下一任务。

### 1.2 功能分解

| ID | 功能 | 本期理解 | 优先级 |
|---|---|---|---|
| F1 | 音频与唤醒 | 空闲常驻录音；按机型选择系统录音或外部 PCM；唤醒后进入会话 | P0 |
| F2 | 对话策略 | 问答与命令分流；交互次数/间隔/超时约束；TTS 与灯效同步 | P0 |
| F3 | 命令到任务 | 导航、介绍播放、舞蹈动作、组合任务；任务中收到新命令先暂停当前任务 | P0 |
| F4 | 任务执行 | 导航抵达后播放欢迎/介绍；介绍可带手势；结束任务执行坐下并切换待机灯 | P0 |
| F5 | 中断恢复 | 任务结束后识别缓存任务，询问恢复；确认恢复、拒绝清除 | P1 |

### 1.3 已列举业务命令

- 问答：非指令语音走语音回答。
- 导航：到迎宾位、历史区、获奖区、具身区、工业区、配送区、清洁区、停靠点。
- 内容介绍：历史、获奖、具身智能、工业、配送、清洁产品；部分要求伴随手势。
- 动作：跳舞。
- 结束："你的工作结束了，可以回去了" → 导航停靠点 → 坐下 → 待机/阻尼模式与待机灯。

## 4. 推荐方案

### 4.1 技术选型

检索摘要（2026-09-15）：Android 官方 `AudioRecord` 需 `RECORD_AUDIO` 且应用必须及时读取缓冲，设备参数应在运行时确认；Android 对麦克风并发采集与后台访问有约束。因此 D9 外接麦应使用单一音频所有者、前台生命周期和设备路由/断连监控。[AudioRecord 官方文档](https://developer.android.com/reference/android/media/AudioRecord)

| 技术点 | 主选 | 理由 | 不选/备选 |
|---|---|---|---|
| 语音会话 | interaction 复用 | 已有多语言、TTS、会话与事件流 | Demo Activity 只适于调试 |
| 音频输入 | `AudioInputProvider` 抽象 | 允许系统录音与 USB/无线麦 PCM 两种实现 | 将采集代码放进 UI 会造成强耦合 |
| 指令分发 | interaction `INTERNAL_APOS` + D9 APOS 能力组件 | 语音、UI、远程等入口复用统一命令总线、条件与状态回传 | 本期固定采用 APOS |
| 状态 | 独立 `D9TaskOrchestrator` | 语音会话与任务生命周期分离，可暂停/恢复 | 在 Activity 回调中堆分支 |
| UI | 原生 Android + interaction 状态事件 | 适配现有 Android/机器人 SDK、弱网与硬件控制 | RN/Flutter/H5 不适合承载低层音频和硬件时序 |

### 4.2 架构与主时序

```mermaid
sequenceDiagram
    participant User as 用户
    participant Audio as D9音频源
    participant Voice as interaction
    participant APOS as APOS命令总线
    participant Task as D9任务编排
    participant Robot as D9机器人能力
    User->>Audio: 说唤醒词或指令
    Audio->>Voice: 系统录音或PCM16k单声道
    Voice-->>User: 唤醒应答和交互灯效事件
    alt 问答
        Voice-->>User: 多语言回答
    else 任务命令
        Voice->>APOS: NLP意图映射为命令及参数
        APOS->>Task: 分发D9能力命令与状态
        Task->>Robot: 暂停旧任务、创建/恢复组合任务
        Robot-->>Task: 进度和终态
        Task-->>APOS: cmdId关联的状态回传
        Task-->>User: 导航、介绍、动作或结束反馈
    end
```

`D9TaskOrchestrator` 维护 `Idle / Executing / Paused / Recovering / Resetting / Finished / Failed`。新语音命令到达 Executing 状态时先持久化可恢复快照、暂停旧任务，再创建新任务；终态统一进入 `Resetting` 和恢复判定，不能由单个导航或播放回调直接开始下一任务。语音意图由 interaction 映射为 APOS 命令，D9 注册 APOS 能力组件执行并回传状态。APOS 原生没有“暂停”状态，因此“暂停/恢复”由编排层通过快照、取消旧命令和重建剩余链路实现，不能假定命令总线自动具备该语义。

## 9. 补充需求：Task 模型、Reset 与异常处理

### 9.1 原子 Task 与 OS 接口

| TaskType | 语义 | OS 调用入口 | 成功终态 | Reset 要求 |
|---|---|---|---|---|
| `NAV_GO_POINT` | 前往点位 | `NavigationManager.startGoalPointNavigation(goal)` | `FINISHED` | 非自然结束时停导航，并确认无运动残留 |
| `LOCO_DANCE` | 跳舞 | `Locomotion.call(SWITCH, rl_dance)` | `FINISHED` | 强制站立 |
| `LOCO_UNDOCK` | 出箱 | `Locomotion.call(CMD_UNDOCK_PILE)` | `FINISHED` | 确认出箱完成、站立 |
| `LOCO_DOCK` | 入箱 | `Locomotion.call(CMD_DOCK_PILE)` | `FINISHED` | 确认入箱完成，再进入阻尼 |
| `LOCO_STAND_UP` | 站立 | `Locomotion.call(CMD_STAND_UP)` | `FINISHED` | 作为动作/异常恢复姿态 |
| `LOCO_DAMPING` | 阻尼/等待 | `Locomotion.call(CMD_DAMPING)` | `FINISHED` | 作为安全终态 |
| `GESTURE` | 手势 | `ManipulateManager.gestureControl(id)` | `FINISHED` | 可用 reset/stand_by 手势收尾 |
| `TTS_PLAY` | 播放话术 | `SpeechManager.startPlayTTS(text)` | `FINISHED` | Error/Cancel 时停止 TTS |
| `LED_SET` | 灯效切换 | `LedManager.turnOn/turnOff` | `FINISHED` | 回到待机灯 |

所有原子 Task 需向统一状态通道回传 `RUNNING / FINISHED / PAUSED / ERROR`。`Reset` 不是普通成功回调，而是所有 FINISHED、ERROR、PAUSED/CANCEL 分支都必须经过的资源/姿态收敛关口，确保下一 Task 可安全启动。

### 9.2 指令到组合 Task 映射

| 指令类别 | 组合任务链 |
|---|---|
| 请到迎宾位 | `UNDOCK → STAND_UP → NAV(welcome) → TTS(欢迎词)` |
| 给大家跳个舞吧 | `STAND_UP → DANCE → STAND_UP` |
| 前往历史区 | `UNDOCK → STAND_UP → NAV(history)` |
| 请介绍历史 | `TTS(历史介绍) ∥ GESTURE`；TTS 先启动，手势按配置延迟 |
| 前往获奖区 | `NAV(award)` |
| 请介绍获奖情况 | `TTS + GESTURE` |
| 前往具身/工业/配送/清洁区 | `NAV(area)` |
| 请介绍对应产品 | `TTS + GESTURE` |
| 可以回去了 | `NAV(home) → DOCK → DAMPING → LED(待机)` |

组合任务由 APOS 下发并按顺序/并行语义编排；不可将 `TTS + GESTURE` 简化为无约束并发，必须配置 TTS 首帧或延迟起手势的同步点。**APOS 中命令数组的排列顺序不等价于串行执行**：每个后继原子命令必须具备唯一 `cmdId`，并以其前驱 `cmdId` 的 `FINISH` 作为 `condition`；无依赖的命令才允许并行启动。

### 9.2.1 P0：APOS 组合任务契约（开发前冻结）

| 契约字段 | 必填性 | 说明 |
|---|---:|---|
| `taskId` / `cmdId` | 必填 | 用于关联语音命令、APOS 命令、D9 任务状态与日志 |
| `command` / `params` | 必填 | D9 APOS Provider 注册的命令名及经校验的参数，例如 `goal`、`text`、`gestureId` |
| `condition` | 串行命令必填 | 后继命令依赖前驱 `FINISH`；不可用下发顺序替代 |
| `priority` / `interruptPolicy` | 必填 | 新语音命令暂停旧任务；急停进入安全终态；其他优先级待冻结 |
| `provider` | 必填 | D9 Provider 负责参数校验、OS 调用、abort/资源释放和状态回传 |
| `stateMapping` | 必填 | 将 APOS `RUNNING / FINISH / FAIL / CANCEL` 映射到 D9 Task 状态；`PAUSED` 由编排快照表达 |
| `resetPolicy` | 必填 | 原子后置收敛与根组合任务终态 Reset 的边界；Reset 完成前不得调度下一任务 |

现阶段只有任务类型和 OS 调用设想，尚不能视为已存在的 D9 APOS Provider；`NAV_GO_POINT`、`LOCO_*`、`GESTURE` 等能力需由 D9 侧注册、实现和验证后才能进入联调。

### 9.3 异常矩阵

| 场景 | 需求处理 | 需要补充的可观察结果 |
|---|---|---|
| 唤醒失败 | 持续录音、继续等待唤醒 | 唤醒失败计数与音频源状态 |
| 指令无法识别 | TTS 再说一次后退出会话 | 重试次数、退出原因、待机灯恢复 |
| 任意 Task ERROR | 停止当前 OS Action，阻尼并上报 ERROR | TaskId、命令、失败码、Reset 结果 |
| Task PAUSED / 急停 | 暂停后站立；急停进入阻尼 | 暂停原因、是否保留恢复快照 |
| 导航/跳舞失败 | 站立后上报 ERROR | 运动停止已确认 |
| 入箱失败 | 阻尼后上报 ERROR | 入箱状态和安全姿态 |
| USB 断开 | 上报 `MIC_ERROR`，尝试切换麦或继续等待唤醒 | 当前音频源、切换结果 |
| 链式 Task 中唤醒 | 非指令直接回答；指令记录未完成 Task 并按中断策略执行 | 原 Task 快照、恢复决策 |
| 按下急停 | 取消全部 Task、站立/阻尼至安全终态 | 清空结果与 APOS 状态回传 |
| 拓扑/定位失败 | 需求要求重试两次后 ERROR | 每次重试及最终错误原因 |

## 10. 模块改造技术方案（仅方案，未实施）

### 10.1 方案选择与模块边界

已确认 D9 实际业务工程只有 call。推荐采用“**interaction 负责通用语音能力，call:libcall 负责 D9 展厅编排和 APOS Provider，ap_os 继续作为命令总线**”的方式。这样语音、多语言、NLP 和 PCM 接入能沉淀到 interaction；D9 点位、话术、手势、运动安全和中断恢复不污染通用 SDK。

| 方案 | 说明 | 结论 |
|---|---|---|
| A：call:libcall 编排 + interaction 扩展 + APOS Provider | interaction 提供无屏语音与外部音频能力；call 内新增展厅域编排；命令统一经 APOS | **采用**：边界与 D9 实际工程一致 |
| B：把 D9 Task 编排写入 interaction | SDK 直接理解 D9 点位、导航、阻尼和手势 | 不采用：会把单机型场景写进通用 SDK |
| C：在 robotopensdk Demo 上直接扩展 | 复用 `MicTestActivity` 的 PCM 流程并叠加业务命令 | 不采用：Demo 不是 D9 的量产业务入口，也不具备 APOS/安全状态闭环 |

```mermaid
graph LR
    A[D9机体麦阵或外接麦] --> B[interaction SDK和logic]
    B --> C[call 展厅语音协调器]
    B --> D[APOS命令总线]
    D --> E[call APOS Provider]
    E --> F[call 展厅任务编排]
    F --> G[D9 OS能力适配器]
    G --> H[导航 运动 手势 TTS 灯效]
    H --> F
    F --> D
```

### 10.4 interaction 的改造职责

| 模块/现有锚点 | 建议改造 | call 的使用方式 |
|---|---|---|

### 10.5 APOS 与 D9 任务的落点

1. interaction 识别到展厅意图后，按 `INTERNAL_APOS` 下发命令；不让 `call:libcall` 绕过 APOS 直调 OS。
2. 新增 `CallAposCommandProvider` 作为展厅命令的唯一 Provider，负责参数合法性、启动、取消入口与错误回传。
3. `ExhibitionTaskOrchestrator` 保存 `taskId ↔ APOS cmdId ↔ D9 OS 调用` 映射。APOS 的 `RUNNING / FINISH / FAIL / CANCEL` 不等同于产品的 `PAUSED`；暂停由编排层保存快照、取消正在执行的 APOS 链路，并在语音确认后重建未完成原子 Task。
4. 串行链路如 `UNDOCK → STAND_UP → NAV` 必须给后继 APOS 命令配置前驱 `FINISH` 条件；`TTS + GESTURE` 只在明确 TTS 首帧/延迟条件后并行。不能以命令数组顺序代替依赖。
5. `Resetting` 是根组合任务的安全关口：OS 动作停止、姿态/灯效收敛并回传 APOS 结果后，才能恢复旧任务或调度下一任务。
